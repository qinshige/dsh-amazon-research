### 以下利润和输出规则只适用于 Trendyol.sa

固定贡献利润：`售价SAR/1.15 - 售价SAR*0.22 - ((采购CNY+计费重kg*68)/1.8+10+5)`。利润≤0或利润率<10%淘汰/谈价，标准件暂估退回15SAR，未知仓库费用不置0。BB评分30/30/15/15/10，仅接受有依据人工分；LD独立页面、独立机会池、不共用排名。样品和实际小批量数据不可能由工具自动替代。

输出：`最终对标品.md`、`淘汰候选.md`、`利润测算.xlsx`、`evidence/`索引、原始输入及SHA-256。三档场景必须提供真实输入，缺失写待确认；工作簿为计算结果快照，手改不自动重算。证据索引不代表已取得截图。

依据用户指定工作流正文实现；其引用的`references/output-templates.md`读取被拒绝，尚未核对该附件。包内沙特技能为标明来源的执行摘要，不冒充原文副本。

## v0.4.9：用户费用口径 + 海空运报价

- 单品筛选（screen / collect 后筛选）和 1688 成本测算默认：**广告 10%、退货损耗 5%、佣金 6%、其它费用 0**。这是用户假设，非平台官方费率。行内明确费用优先于口径档。
- `costProfile` 可覆盖费率，比率用小数（如 0.10）。
- `freightMode: "sea" | "air"` 选择海运/空运；`freightPerKgCNY` 手动报价优先，否则用 `freightApiUrl`。缺失/失败不套估价、不补零；需有件重或逐件头程报价才算净利。
- 接口协议 **CNY/kg**，示例：`{"rates":{"sea":20,"air":50},"currency":"CNY","unit":"kg","quotedAt":"2026-11-17","validUntil":"2026-11-18"}`。数字仅为协议示例，不是当前报价。不支持直接套用每立方米报价；线路、体积重、最低计费重与附加费需向报价方确认。
- 没有内置通用货代服务，需提供适用线路接口或确认后的报价；报告区分报价日期、抓取时间、来源，缺日期显示未取到。
- 汇率取接口最新公布值，最多缓存30分钟；尊重手动汇率。失败保持6.7/6.6回退并标注default，不冒充实时。
- FBA/履约成本仍独立列示，不包含在其它费用0内；这是指定成本项下的利润测算，不等于完整财务利润。低层旧模型保留显式估算兼容路径，工具入口使用上述缺数保护。
- 宿主模块修改需重新加载插件或重启当前DSH。本次未改前端资源，不需另起Web服务。

用户口径「汇率可以按照实时的计算」，所以**实时汇率成为默认**：

## v0.4.7：双汇率（成本 6.7 / 结算 6.6）+ 人民币利润

用户口径：**成本按 6.7 折算，结算（利润）按 6.6**。两者不同会导致系统性偏差：
成本项按高汇率折美元会**低估**成本，美元收入按低汇率折人民币会**低估**回款 —— 两头都往不利方向偏。

新增 `host/fx.js`：

| 概念 | 默认 | 用途 |
| --- | --- | --- |
| 成本汇率 costFx | **6.7** | 把人民币成本（1688 采购价、头程 ¥/kg）折成美元 |
| 结算汇率 settleFx | **6.6** | 把美元收入与利润折成人民币结算 |

- 计算仍以**美元**为基准做成本/收入相减（净利率口径不变），只是在输出层多给人民币金额：
  `netProfitCNY` / `totalCostCNY` / `priceCNY_settle`；
- 净利率**不受结算汇率影响**（收入与成本同在美元口径），但人民币利润额会随结算汇率变；
- 采购价上限倒推（`maxPurchaseCNYForNetMargin`）按**成本汇率**折算 —— 采购是人民币成本，与结算汇率无关；
- 工具参数：`costFx` / `settleFx` / `liveFx`（取实时汇率，取不到自动回落默认值并在报告标注来源）；
- 实时汇率走 `open.er-api.com` 与 `frankfurter.app`，实测取到 6.6793；取不到**不报错**，回落默认值；
- 报告新增列：渠道对照「单件净利¥ / 单件总成本¥」、优先候选与全部候选「单件净利¥」、
  净利率输入「总成本¥ / 净利¥」。

## v0.4.2：数据可信度体系（全量采集 + 采价校验 + 分段利润 + 依据链）

针对「分析结果必须准确、数据必须找齐、不要一上来就否决」的要求，新增四道机制：

**1. 采价校验器 `host/selection/verify.js`** — 任何 1688 报价进利润测算前必须过三道闸：
- 同一性：1688 标题必须命中该 Amazon 品的品类词，且不得命中排除词
  （实测事故：关键词「手套夹 20个装」搜到「5-10人装扎染材料包…一次性手套(50双)」，含「手套」被误匹配）；
- 件数一致：Amazon 件数 与 1688 规格件数一致，否则按「单件价 × 件数」折算
  （实测事故：¥1.70/个 当成 20 个装整包价 → 采购成本低估 20 倍，净利率 13.8% 虚报成 48.4%）；
- 重量一致：Amazon 包装重 ÷ 件数 ≈ 1688 单重（±50%），两边独立数据交叉验证。

通过后给出置信度 high / medium / low；low 及以下**不参与利润测算**，报告显示「未通过校验」。

**2. 全量采集 `host/selection/collect-full.js` + `detail-enrich.js`** — 多关键词 × 多页 Amazon 搜索 + 逐个详情页补齐
（件数、包装尺寸重量、品牌、上架日期、BSR、卖家、变体选项）。目标 Top 50–100+，不再只看前几个。
复用同一个标签页循环导航（每页开新标签会把 Chrome 堆到上百个）。

**3. 分段利润 `host/selection/segments.js`** — 回答「第 50–100 名还有没有利润」：
按销量切四段（头部 1–10 / 腰部 11–30 / 中长尾 31–50 / 长尾 51–100），
每段给平均售价、评论数、变体数、平均与中位净利率、正利润占比、以及**能不能做 + 为什么**。
头部集中度高往往说明**头部很贵**（评论壁垒高），机会常在腰部与长尾。

**4. 否决依据链 `host/selection/evidence.js`** — 每条否决给出：依据数值、阈值、数据来源、可信度；
报告新增「数据可信度总览」（高/中/低各多少个、缺什么）。

**5. 画像适配分级** — 画像不适配区分「硬性冲突」（认证、大件）与「可换切入点」（售价带、变体、季节、利润），
后者给可操作建议而不是一句「不做」。

  - `tiktok-shop`：佣金 **6%**（TikTok Shop 美国站 2026-10 费率表）、**无 FBA 费**、跨境直发物流（默认 $2.20/件 + $8/kg 估算）、达人佣金/广告 12%、退货 8%。
- `research_product_select` 新增 `channel` 参数；平台佣金随渠道走（采集表里的类目佣金只用于 Amazon 渠道）。
- 卖家画像价格带按渠道切换（新手带：Amazon $15–35 / TK $8–25）。
- 报告新增「1.3 渠道对照」：同一个品在三个渠道的净利率并排，并标注各行口径警告。
- 修复：TK 渠道下首批资金漏算跨境运费（头程已并入履约成本）。

> **为什么必须有**：实测 Work Glove Holders 4 件装（售价 $5.49、56g）：
> Amazon FBA 的小号标准件配送费 $3.22 吃掉 **59% 收入** → 必亏（−5.2%）；
> TikTok Shop 佣金 6%、无 FBA 费 → **+25.7%**。同一个品，换渠道结论完全相反。
> 只按一个渠道判生死，会对做 TK / 独立站 / 线下渠道的卖家系统性误判。

### 数据与评分边界

关键词搜索结果是样本，非全类目；抓取顺序不是畅销排名。月销量、月销额、平台自营占比、卖家集中度及利润未取到，不补零、不推算。

实验模型 trendyol-review-proxy-v1：市场活跃度用样本累计计数（TR 评论数；SA 评价数，含仅评分、非文字评论）；增长/机会用计数 <100 的商品数占比（仅以有计数字段的样本为分母）；CR3/HHI 用已知品牌计数权重并披露覆盖率。自营缺数占位 3/10，利润缺数 0/12，不代表真实利润为零。总分仍为92，归一化 total/92×100；**与 Amazon 以及不同国家样本不可横比，评级不构成进入建议**。价格随目标国家使用 TRY/TL 或 SAR，不套用美元利润档位。沙特搜索卡片展示价可能附带结算折扣；会员专享价不混入普通价格统计，缺失保持未取到。具体阈值见独立报告说明。

报告输出：Markdown、HTML 表格看板、market/manifest/scores JSON、商品及品牌 CSV。保存原始抓取时间、生成时间、来源链接、样本覆盖和缺失说明。

## 这个插件解决什么问题

跨境选品里最贵的错误不是「选错品」，而是**用错口径算出来的利润**。市面上的选品报告普遍有两个洞：

1. **利润用毛利率冒充净利率** —— 毛利率只扣采购成本，不扣佣金、广告、退货、头程、FBA。一个毛利率 60% 的品，算完全成本可能是 −9%。
2. **采购价拿单件价对多件装售价** —— 1688 上脚垫 ¥0.25/个是单件价，Amazon 卖的是 48/104/162 片装。直接相减会把采购成本低估 10~100 倍。

本插件的每一个数字都带口径标注，取不到就写「未取到」，**不用经验值补齐**。

### 数据可追溯：每个数字怎么核

每次运行是一个独立目录，产物固定：

    <outDir>/<runId>/
      manifest.json          运行元信息（runId、站点、时间、输入指纹）
      provenance.json        原始输入行 + 逐项判定 + 输入指纹（新增）
      selection-scores.json  分档、KPI、否决、差异化
      report.md              中文报告
      selection.csv          可直接回填的明细表

报告第八章给出四条追溯链：

| 小节 | 内容 | 用途 |
| --- | --- | --- |
| 8.1 追溯信息 | 运行 ID、输入指纹（SHA-256）、候选数、来源、汇率、产物清单 | 核对报告是否对应同一批输入 |
| 8.2 逐品来源 | 每个 ASIN 的商品链接、1688 链接、采集时间、来源标注、缺失字段 | 回到原页面复核 |
| 8.3 指标取数列 | 每个 KPI 来自哪一列、证据类型（采集值/计算值/人工判断） | 知道数字从哪来 |
| 8.4 净利率计算输入 | 售价、采购价、件重、FBA、广告、退货、佣金、头程、其它 | 复算利润 |

输入指纹规则：对输入行做键排序后 SHA-256；同一份采集表 + 同一汇率得到同一个指纹，改任一字段指纹就变。报告被改过、或换了数据，用指纹一比就知道。

缺失字段的处理：一律写「未取到 / 未知」，不计入命中率分母，不按 0 处理，也不用行业常识补。估算值（FBA、头程、汇率、默认广告/退货率）在报告里单独标注「估」；采购价、件重等必须来自 1688 详情页或页面实测。

## 方法论

### 〇、选品全流程（四途径 → 九策略 → 十维 → 差异化）

```
四途径（从哪找）   站内 7 个榜单/热搜 + 站外平台 + 软件 + 线下
      ↓
九策略（怎么筛）   细分 / 竞品店铺 / 跨站点 / 关联 / 交叉 / 同场景 / 高单价 / 新型市场 / 热门载体
      ↓
十维（看什么数）   容量与竞争、趋势、价格、评分评价、新品、季节、质量退货、物流、供应链、侵权认证（+ 利润）
      ↓
定品与差异化       一票否决 → 一档/二档/三档/待复核/淘汰 → 差异化方向 → 小批量测款
```

| 步骤 | 工具 |
|---|---|
| 出路线图（榜单链接、九策略适用性、十维清单） | `research_product_select { action: "plan" }` |
| 类目大盘与五维评分 | `research_category_select` |
| 候选 ASIN 十维体检与报告 | `research_product_select { action: "screen", rows: [...] }` |
| 1688 采价与净利重算 | `research_unit_cost` |
| 读历史报告 | `research_runs` |

**一票否决**：大类目（< 3 级）、品牌集中度 > 70%、前 10 评价 > 10000、变体 > 3、专利/商标风险、易碎/抛货、退货 > 10% 且差评不可解决、净利率 < 15%。

**分档**：一档 = 无否决 + 命中率 ≥ 80% + 净利率 > 30%；二档 = 无否决 + 命中率 ≥ 60% + 净利率 ≥ 25%（小体量 > 30%）；其余三档；缺净利率或可判定 KPI < 6 项为待复核。

**差异化**：外在（颜色、数量、SKU、包装、主图、说明书）+ 内在（人群、场景、材质、外观、功能组合、防退货、认证前置），每条建议必须挂真实证据。

### 一、五维评分（92 分制）

五个维度独立打分，**原始上限 92 分**（不是 100），归一化后给出评级：

| 维度 | 满分 | 看什么 |
|---|---|---|
| 市场规模 | 20 | 月销额、销量、在售商品数 |
| 增长潜力 | 22 | 低评论商品销量占比（评论数 < 300，非趋势、非新品占比） |
| 竞争烈度 | 18 | Top3 品牌/商品/卖家集中度、品牌 HHI |
| 进入壁垒 | 20 | Amazon 自营占比、新品占比、评论壁垒 |
| 利润空间 | 12 | 全成本净利率（见下） |

```
归一化 = 总分 ÷ 92 × 100
评级：≥80 优秀 ／ ≥60 良好 ／ ≥40 一般 ／ <40 较差
```

**缺数不编造**：某维度取不到数据就按该维度最低档计，并在报告里写明「按最低档计（不编造数据）」。缺 ≥2 个维度时结论降级为「数据质量 C，补数后再评」，不再输出「强烈推荐」。

**HHI 是品牌级口径**（0~10000）。按商品级份额算 HHI 是常见错误，会把集中度严重低估。

### 二、全成本净利测算

利润空间维度用**净利率**而非毛利率：

```
净利率 = (售价 − 采购 − 头程 − FBA − 佣金 − 广告 − 退货 − 其它) ÷ 售价
```

判定红线：

| 红线 | 阈值 |
|---|---|
| 净利率 | > 25% 才考虑；体量小（100~200 单）需 > 30% |
| 物流占售价（头程+FBA） | 10%~15% 为理想带；> 20% 提示放弃 |
| 采购价占售价 | ≤ 25% |
| $15~20 售价段 | 采购价 ≤ ¥30 且 FBA < $4.5 |

估算参数（汇率、头程 ¥/kg、佣金、广告、退货、其它）全部在报告里标注「估算值」；采购价、件重、起批量、材质、代发来自详情页真实文本，标注「实测值」。

### 三、包装规格对齐（最容易出错的一环）

1688 的入口价几乎都是**单件价**，Amazon 售价对应的是**一个可售单位**。插件的处理：

1. 从 1688 详情页取**多件装档**（例：`4个装¥1 / 8个装¥2.2 / 16个装¥4.5 / 20个装¥5.5`）
2. 从 Amazon 前台搜索页标题**实测包装数**（每细分约 48 条结果取中位）
3. 按目标包装数选整包数，算出「一个可售单位的真实采购成本」

三种特殊档位都单独处理：规格写成「1件/20个」的（脚垫，¥0.35 是整件价）、按面积计价的（篷布，¥5.5/9 平方）、物流包装当售卖规格的（拉手，200个/盒）。

推导过程写入 `tables/pack_alignment.csv`。

### 四、数据来源与频率

| 数据 | 来源 | 频率 |
|---|---|---|
| 类目大盘、分布、Top 商品 | 卖家精灵 | 每次运行 |
| 采购价、阶梯价、件重、材质 | 1688 详情页 | 每次采价 |

## 数据源

### 卖家精灵：两条链路

| provider | 取数方式 | 消耗 | 何时用 |
|---|---|---|---|
| `sellersprite` | 卖家精灵官方 MCP | 9~11 次调用/次（额度） | 账号已开通 MCP 服务权限 |
| `sellersprite-web` | 你 Chrome 里已登录的卖家精灵**网页版** | 网页端查询次数 | MCP 报 `TOOL_NOT_ALLOWED` / `secret_unauthorized` 时 |

`research_category_select` 传 `provider` 切换。

网页链路读取**你自己的登录态**，不绕过任何鉴权、不过验证码、不破解限制。它能取到「选市场 / 类目报告 / 查竞品」三页数据，但没有 `market_*` 分布工具——价格带、评论数、上架时间分布由 **Top N 父体样本推导**，报告会显式标注口径。

> 两条链路的分布口径不同（一个是类目全量，一个是样本推导），**两次 run 的分数不可并列排名**。

### 1688

`research_unit_cost` 按子市场关键词搜索货源，进入详情页逐项验证：阶梯价、起批量、材质、SKU 变体、件重、包装尺寸、供应商、一件代发标识。

**搜索页有频控**（连跑约 5 个关键词会撞滑块验证码），插件命中即抛 `CAPTCHA` 并停手；详情页基本不拦。

## 性能

面板的 `overview` 请求会顺带探测各数据源状态，因此所有探针都必须有超时保护：

| 探针 | 耗时 | 说明 |
|---|---|---|
| 卖家精灵 MCP | 视网络 | 只查密钥配置，不发网络请求 |
| 卖家精灵网页链路 | ~2.4s（首次）／~0ms（缓存） | 只列浏览器标签页判断登录态，**不打开数据页**；TTL 60 秒 |
| 运行记录扫描 | ~10ms | 扫候选根目录 + 读运行登记表 |

浏览器自动化探针一旦失控就会拖垮整个面板请求（前端超时 8 秒），因此：

- 网页链路的 `health()` **只列标签页**，不抓数据页；
- 状态探测有 60 秒 TTL 缓存；
- `routes.js` 与 `providers.js` 各有一层超时兜底（2.5 秒 / 2 秒）。

`test/panel-latency.test.mjs` 用静态断言守住这些不变量。

## 已知限制

- 当前只做**品类选品**；ASIN 体检 / 词库 / 差评分析 / Listing builder 在后续版本
- 只接入了卖家精灵（自备 key）；Sorftime 适配代码保留但未验收
- 利润维度未接 1688 采购成本时按价格带估算，报告会显式标注「仅供初筛」
- 网页登录态链路依赖 macOS + Google Chrome + AppleScript，其他平台需自行实现 `host/web/chrome.js`
- 网页链路没有 `market_*` 分布工具，分布由 Top N 父体样本推导（已标注口径）
- 包装规格对齐依赖 Amazon 前台搜索页标题实测；样本不足的细分（如 Tarps 仅 1 条）已标注置信度低
- 1688 搜索页频控约 5 个关键词；命中验证码即停手报错，不绕过

## 数据纪律

本插件遵循三条硬规则：

1. **所有数字必须来自工具返回**，缺失写「未取到」并说明，不用常识补齐
2. **每次结论附数据来源与抓取时间**，估算值与实测值分开标注
3. **不用经验值代替缺失数据**——缺就降级结论，而不是猜一个
