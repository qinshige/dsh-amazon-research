# 类目选品报告骨架（Report Outline）

引擎会在运行目录生成 `report.md` 初稿（以及 `dashboard.html`、`tables/*.csv`）。本文件规定**报告应该长什么样、每章要回答什么问题、哪些话不能写**。

- 引擎初稿已覆盖的章节：在初稿上**补结论、补解读、纠措辞**，不要推翻重造数据。
- 引擎初稿缺失/过简的章节：按本骨架补齐。
- 任何结论都必须能追溯到 `market.json`/`scores.json` 的字段；写不出出处的句子删掉。

## 1. 报告骨架总览

| # | 章节 | 必须 | 核心问题 | 主要数据来源 |
| --- | --- | --- | --- | --- |
| 0 | 报告头部元信息 | ✅ | 这份报告是什么时候、用什么口径算的？ | manifest / market |
| 1 | 结论摘要 | ✅ | 能不能做？一句话结论 + 评级 + 3 条理由 | scores / 各章 |
| 2 | 五维评分 | ✅ | 多少分、每维为什么是这个分、缺了什么 | scores.json |
| 3 | 市场大盘 | ✅ | 盘子多大、均价多少、结构如何 | market.totals/avgs/structure/newRatio |
| 4 | 竞争与集中度 | ✅ | 头部垄断到什么程度、谁在卖 | concentration / distributions.brand / sellerCountry |
| 5 | 价格带 | ✅ | 主流价格带在哪、利润缝隙在哪 | distributions.price |
| 6 | 新品与需求 | 建议 | 新品有没有机会、评论墙多高、季节性如何 | newRatio / ratingsCount / listingDate（+补 demandTrend） |
| 7 | 风险与降级项 | ✅ | 哪些点会让结论打折 | 全章汇总 + warnings |
| 8 | 进入建议与验证 | ✅ | 从哪进、先做什么、怎么验证失败 | 前 7 章推导 |
| 9 | 附录：数据来源与口径 | ✅ | 可复盘、可追溯 | manifest / artifacts / 补数记录 |

> 报告通常 3–5 屏（约 1200–2500 字）+ 表格；用户只要「快报」时压缩成 1 屏（第 0/1/2/5/7 节的一句版）。
> 引擎初稿是 7 章：一、结论摘要｜二、五维评分｜三、市场大盘｜四、品牌与卖家集中度｜五、价格带与评论结构｜六、风险与一票否决提示｜七、数据来源与缺失清单（+ 附录 Top 10 产品）。它与本骨架**内容对应但序号不同**：以**内容齐全**为准，在初稿上补「数据质量等级、进入建议与验证动作、缺数据说明」，不要为了对齐章号重写引擎已有内容，也不要让同一内容重复两遍。

## 2. 各章要点

### 第 0 章｜报告头部元信息（固定模板）

```text
类目选品报告｜<类目英文名>｜<站点>
数据来源：SellerSprite（runId: <runId>）
NodeIdPath：<nodeIdPath>
数据月份：<yyyy-MM 或「最近已就绪自然月（未显式指定）」>
抓取时间：<fetchedAt UTC>（北京时间 <本地时间>）｜生成时间：<createdAt>
样本口径：Top <limit>（抽样口径，真实 N=limit；样本 <100 已标注）
成本口径：unitCost = <$x.xx/件 | 未提供，利润维度按价格带估算（仅供初筛）>
数据质量：<A/B/C/D>
```

- 缺任何一项都算报告不完整；数据月份为空串时不能编一个具体月份。
- `data quality` 按 `references/data-rules.md` 第 8 节判。

### 第 1 章｜结论摘要（先给答案）

必须包含 5 行以内：

1. **结论**：推荐进入 / 谨慎试验 / 放弃。
2. **评级**：normalized xx.x（grade），总分 xx/92。
3. **三条关键理由**：每条带字段 + 数值 + 数据月份，例如「Top3 品牌销量占比 26.4%，格局分散」。
4. **进入建议**：目标价格带 + 差异化方向一句话。
5. **数据缺口/置信度**：缺什么、结论要不要打折。

> 不能出现「综合来看不错」这种没有依据的总结；摘要里的每个数字都要在正文有对应表格。

### 第 2 章｜五维评分

表格列：维度 / 得分 / 满分（实际最高）/ 关键输入 / 说明（缺数据/异常）。

```text
| 维度 | 得分 | 满分（实际最高） | 关键输入 | 说明 |
| 市场规模 | 20 | 20 | 样本月销额 $18.6M | >$10M，最高档 |
| 增长潜力 | 18 | 25（22） | 低评论销量占比 38.2% | >20% 未过 40% |
| 竞争烈度 | 18 | 20（18） | Top3 品牌占比 26.4% | <30%，分散 |
| 进入壁垒 | 16 | 20 | Amazon 自营 5.2%；低评论占比 38.2% | 10 + 6 |
| 利润空间 | 7 | 15（12） | 均价 $268.0；unitCost 未提供 | avg_price 模式，仅供初筛 |
| 合计 | 79 | 92 | normalized = 79/92×100 = 85.9 | 优秀（≥80） |
```

- 必须解释「为什么是这个档」，不要只抄分；每维解释可直接引用 `scores.json` 的 `dimensions[].detail`（含口径与档位说明），不要自己改写成另一套阈值。
- 缺数据维度写「最低档 + 原因」；`unitCost` 未提供时利润维必须标「价格带估算，仅供初筛」。
- 不要出现 100 分制说法；不要说「满分 100」。

### 第 3 章｜市场大盘

表格列：指标 / 数值 / 口径/说明。至少覆盖：

| 指标 | 字段 | 写法 |
| --- | --- | --- |
| 在售商品数 | `totals.products` | 整数；若为 0 标「数据异常」 |
| 样本月销量 | `totals.units` | 千分位 |
| 样本月销额 | `totals.revenue` | 币种 + 千分位 |
| 平均价格 | `avgs.price` | $xx.xx |
| 平均 BSR/评分/评分数 | `avgs.bsr/rating/ratings` | 缺失标「未取到」 |
| 卖家结构 | `structure.fba/fbm/amazonSelfProportion` | 已是百分数，写 xx.x% |
| 退货率 | `structure.returnRatio` | 已是百分数；无同类基线时只陈述数值不做好坏判断 |
| 新品占比 | `newRatio.l1/l3/l6/l12` | 0~1 ×100；注明「近 1/3/6/12 个月上架」 |

解读只写有依据的 2–3 句：盘子大不大、价格带粗定位、自营挤压程度、新品活跃度。

### 第 4 章｜竞争与集中度

1. **集中度表**：`top3ProductCrn`、`top3BrandCrn`、`top3SellerCrn`、`top5BrandCrn`、`top10BrandCrn`，统一 ×100 写 %，注明口径（品牌/商品/卖家、Top3/5/10）。若引擎给了**品牌 HHI**（0~10000）：按 <1500 低 / <2500 中 / ≥2500 高解读，必须标「0~10000 刻度」，不要与 CRn 的 0~1 混写。
2. **头部品牌表**：来自 `distributions.brand`，列品牌 / 商品数 / 月销量 / 月销额 / 销量占比 / 均价 / 评分。按销量占比降序，取前 8–10。
3. **卖家所属地表**：来自 `distributions.sellerCountry`，列国家/地区 + 销量占比；用于判断中国卖家竞争强度。
4. **读法**：<30% 分散 / 30–50% 中等 / >50% 集中（经验阈值，写「经验阈值」或「本报告判读」）。
5. 若 `sellerType` 未取到，在章末写「履约结构（FBA/FBM/AMZ）未取到」；有补数才写补数结论。

### 第 5 章｜价格带

1. **价格带表**：来自 `distributions.price`，列价格带 / 商品数 / 月销量 / 月销额 / 销量占比。按 `unitsRatio` 降序。
2. **主流价格带**：销量占比最高的 1–2 段；写出「占销量 xx%，均价 $xx」。
3. **利润缝隙**：高价格带中 `unitsRatio` 低但 `revenue` 占比不低、且评分数分布未被高评论垄断的段；没有证据就不写。
4. **价格战警示**：主流带 >60% 销量且均价低 → 明确写「价格带集中且价格低，新进入毛利承压」，不要只列数字。
5. 若本次 run 传了 `unitCost`（`scores.json` 里 `basis='unit_cost'`）：加一小节「按 unitCost 的毛利测算」，列 (均价 - unitCost - 附加成本)/均价 与档位，并注明这是**评分输入**；若用户提供了成本但 run 未传（`basis='avg_price'`），写明「未进入评分，建议带 unitCost 重跑」，不要手工改分。

### 第 6 章｜新品与需求（建议章）

- **新品占比**：`newRatio.l1/l3/l6/l12` 四个窗口，写「新品在类目销量中的占比（0~1）」，不要写成数量。
- **上架时间分布**：`distributions.listingDate`，看新品/老品结构；样本小时可能全 0 → 标「未取到/样本不足」。
- **评论墙**：`distributions.ratingsCount`，看高评论段销量占比，说明「新品冷启动需要多少评论量级」时只做定性提示（没有行业阈值就不下定量结论）。
- **季节性**：`demandTrend` 在 v0.1 为空；需要就 `mcp_call` 补 `market_product_demand_trend`，否则写「未取到，不判断季节性」。
- 结论只回答：新品有没有缝、评论墙高不高、进入窗口是否在收窄。

### 第 7 章｜风险与降级项

用清单/表格，每条「风险 + 数据依据 + 影响 + 建议」：

| 风险 | 数据依据 | 影响 |
| --- | --- | --- |
| 头部品牌垄断 | Top3 品牌占比 52%（>50%） | 新品牌需差异化或换价格带 |
| Amazon 自营挤压 | amazonSelfProportion = 35% | 第三方份额受限，结论降档 |
| 评论墙高 | ratingsCount Top 段占销量 61% | 冷启动成本高，预算要覆盖测评/广告 |
| 退货率偏高 | returnRatio = 12.4%（同类目未取到基线） | 售后与利润不确定，只做陈述 |
| 数据缺口 | 卖家类型分布未取到 | 履约门槛判断不完整，数据质量 B |
| 价格带过低 | 均价 <$15（引擎一票否决检查项） | 物流/佣金占比高，利润空间受限 |
| HHI 高集中 | 品牌 HHI ≥2500（0~10000） | 头部集中，窗口收窄 |
| 合规敏感 | 涉及儿童/电子/医疗宣称 | 需人工核验认证，不在本报告做定性 |

必须包含「本次数据缺口」与「结论置信度」两行；缺 ≥2 维时报告结论区已由数据质量守卫显示「数据质量 C/D（N 个维度缺数）：兜底评级仅供参考，建议补数后再评，不构成进入建议」——保留该措辞，不要改写为推荐；结论摘要与第 8 章进入建议相应降级为「先补数/小规模验证」。

### 第 8 章｜进入建议与验证

只写类目级可执行动作，不写单品 Listing/广告细节：

1. **进入价格带**：目标带 + 依据（主流带/利润缝隙）。
2. **差异化方向**：2–3 个方向（价格带错位、材质/场景/组合、评论痛点驱动），每个都要能指回价格带/评论墙/结构数据。
3. **首批规模**：建议小批量 SKU 数 × 首批件数（如「1–2 个 SKU，各 200–300 件」）——这是**建议**不是数据，标明是基于预算的推断。
4. **验证指标与观察期**：8 周内看动销、评论增速、退货率、广告 ACOS 等；给「继续/停止」判定条件。
5. **下一步补数**：若数据质量 B/C，列出补数动作与预计消耗（约 9~11 次调用或 mcp_call 次数）。

### 第 9 章｜附录：数据来源与口径

必须包含：

- 数据源与 runId、运行目录、`artifacts` 清单（manifest/market/scores/report/dashboard/tables）。
- 参数：`marketplace`、`category`/`nodeIdPath`、`limit`、`month`、`unitCost`、`provider`。
- 抓取时间、生成时间、`usage`（calls/errors/totalMs）。
- `warnings` 原文（不要删，逐条列）。
- 补数记录（如有）：provider、tool、args、抓取时间、savedTo。
- 引用文件：`tables/market.csv`、`tables/brands.csv`、`tables/price_bands.csv`、`tables/top_products.csv`、`dashboard.html`。

## 3. 格式规范

| 项 | 规范 |
| --- | --- |
| 金额 | 站点币种符号 + 千分位（$18,600,000）；大额可写 $18.6M 但首次出现给全称 |
| 百分比 | 1 位小数（26.4%）；0~1 小数先 ×100，不要同时出现 0.264 和 26.4% |
| 数量 | 千分位（12,345 件） |
| 缺失 | 「未取到」或「—」（表格），不留空、不写 0 |
| 日期 | 数据月份 `yyyy-MM`；抓取时间 ISO UTC + 北京时间 |
| 评级 | 「优秀（≥80）/ 良好（≥60）/ 一般（≥40）/ 较差（<40）」，归一化到 100 后判断 |
| 口径 | 每个表格标题下注一行「口径：样本 Top N；数据月份；来源」 |
| 估算 | 必须标「推算（公式 + 输入）」，与数据分开呈现 |
| 来源 | 正文引用字段名或表格名；附录给完整来源 |

## 5. 快报模式（用户只要结论时）

1 屏以内，保留：头部元信息 + 结论/评级/三条理由 + 主流价格带 + 风险 2 条 + 数据质量。表格压成 1 个评分表。**仍不能省略来源、数据月份、抓取时间、缺口标注。**

## 6. 报告质量检查清单

- [ ] 头部元信息齐全（含 runId、NodeIdPath、数据月份、抓取时间、样本口径、数据质量）。
- [ ] 结论 = 三选一，且与 normalized/grade、降档规则一致。
- [ ] 摘要里的每个数字都能在正文表格找到。
- [ ] 五维表与 `scores.json` 一致，未出现 100 分制表述。
- [ ] 集中度/价格带/大盘的百分数与 `market.json` 一致，刻度未混用。
- [ ] 缺失数据全部标「未取到」，没有 0 值替代、没有编造。
- [ ] 有「风险与数据缺口」章；缺 ≥2 维时报告已含数据质量守卫措辞（`dataQuality` C/D、「补数后再评，不构成进入建议」），结论区无「推荐进入」。
- [ ] 有「附录：数据来源与口径」，含 warnings 与补数记录。
- [ ] 报告未出现密钥/敏感参数，未越界做单品、专利、合规定性。
- [ ] 与 `dashboard.html`/`tables/*.csv` 数字一致；如不一致，以 `market.json/scores.json` 为准并修正所有产物。

## 7. 常见坏味道（看到就改）

| 坏味道 | 修正 |
| --- | --- |
| 「市场很大，机会不错」 | 换成「样本月销额 $18.6M（2026-10），规模档位最高」 |
| 「竞争适中」 | 换成「Top3 品牌占比 41.2%，按本报告经验阈值属中等集中」 |
| 「利润率约 30%」但没给成本 | 删掉，或改成「unitCost 未提供，利润维度按价格带估算，未做净利测算」 |
| 「预计增长 20%」 | 删掉预测，改成「l6 新品占比 8.3%，新品仍在出单（现状描述）」 |
| 「评分 92/100」 | 改成「总分 92/92（normalized 100），注意本模型满分上限为 92」 |
| 表格里 0 与「未取到」混用 | 按 data-rules 第 4 节重判 |
| 报告只有结论没有附录 | 补附录；没有来源的报告等于没有报告 |
