# 数据规则（Data Rules）

本文件规定「数据从哪来、什么时候抓的、缺了怎么写、能不能重跑、花钱怎么说、什么绝对不能编」。所有类目选品输出都必须遵守；与 SKILL.md 冲突时，以本文件的数据纪律为准。

## 1. 适用范围

- 插件 v0.1，数据源仅 **卖家精灵 SellerSprite**；类目取数只通过 `research_category_select`，补数只通过 `mcp_call`。
- `research_category_select` 有两条链路：`provider:'sellersprite'`（官方 MCP，消耗额度）与 `provider:'sellersprite-web'`（用户 Chrome 里已登录的卖家精灵网页版，不消耗 MCP 额度、改为占用网页端查询次数）。两条链路的数据口径不同，**不可并列排名**。
- 数据落盘在本地运行目录（`<outDir>/<YYYYMMDD>_<slug>_<站点>/`）；`research_runs` 只读本地，不产生费用。
- 本文件不涉及单品 Listing、关键词、评论、广告数据——v0.1 没有这些高层工具。

## 2. 数据来源与时间戳

### 2.1 唯一可信链路

```text
SellerSprite MCP 原始响应
  → 插件归一层（host/normalize.js）
  → market.json（归一化 Market，唯一分析输入）
  → scores.json（评分明细） + report.md（报告初稿）
```

**报告里的数字只能来自这条链路或一次有记录的 mcp_call 补数**。模型自己的记忆、网页搜索、行业文章、上游示例报告里的数字，都不能当成本次数据。

### 2.2 三个时间概念，不要混

| 时间 | 字段 | 含义 | 写法 |
| --- | --- | --- | --- |
| 抓取时间 | `manifest.fetchedAt` / `market.fetchedAt`（ISO 8601 UTC） | 本次真正向数据源取数的时刻 | 报告写「抓取时间：2026-11-10T15:00:00Z（北京时间 11-10 23:00）」 |
| 数据月份 | `manifest.month` / `market.month`（yyyy-MM 或空串） | 数据统计所属月份 | 空串表示未显式指定，报告写「最近已就绪自然月（未显式指定）」并注明是口径假设 |
| 生成时间 | `manifest.createdAt` / `report` 生成时间 | 本次运行落盘时刻 | 可与抓取时间不同（取数 → 评分 → 写盘），报告标「生成时间」 |

- **不要**把抓取时间写成数据月份，也不要把数据月份写成「今天/本月」。
- 月度数据通常有延迟；禁止写「实时销量」「当前价格」。
- 展示给用户时统一到北京时间并注明 UTC 原文；跨时区用户以用户所在时区说明。

### 2.3 报告头部的固定元信息

每个报告/结论必须包含（缺一不可）：

```text
数据来源：SellerSprite（runId: 20261110_wireless_microphones_US）
站点：US        类目：Wireless Microphones & Systems
NodeIdPath：11091801:11974521:8882489011
数据月份：2026-10（或「最近已就绪自然月（未显式指定）」）
抓取时间：2026-11-10T15:00:00Z（北京时间 23:00）
样本口径：Top 50（limit=50；销额/销量为抽样口径，真实 N 以 manifest.params.limit 为准，样本不足 100 已在结论标注）
成本口径：unitCost 未提供 → 利润维度按价格带估算，仅供初筛
```

> **网页登录态（`provider:'sellersprite-web'`）追加两行**（缺一不可）：
>
> ```text
> 取数链路：网页登录态 sellersprite-web（选市场 → 类目报告 → 查竞品，3 次页面读取；分布为 Top N 样本推导）
> 样本口径：Top 30 样本推导（N=30，取自 market.json 实际商品数，非 limit；分布非类目全量）
> ```

## 3. 字段口径与单位

| 口径 | 规则 |
| --- | --- |
| 币种 | 站点本币（US 为 USD）；不要把 USD 与 CNY 混算；采购成本 `unitCost` 明确是 USD/件（采购+头程） |
| 金额/数量 | `totalRevenue` 是样本销售额，`totalUnits` 是样本销量；均值字段是**样本均值**，不是全类目均值 |
| 比例 | 集中度/新品占比是 0~1 小数，展示 ×100；卖家结构/退货率已是百分数，不再换算（详见市场指南第 5 节） |
| 样本 | `limit`（10–100）决定 Top N 样本；集中度、均值都随样本变化，不同 `limit` 的 run 不能直接比大小 |
| 时间 | 月度口径；不要把某月数据说成「30 天滚动」或「近 7 天」；指定 `month` 时，v0.1 只影响 6 个分布工具，`market_research` 大盘仍为厂商默认最近月，报告必须标「大盘/分布月份口径可能不同步」 |
| 均值 vs 中位 | 只有均值字段时不要声称「中位数」；需要中位数得看原始分布或明确标「未取到」 |
| 集中度 vs HHI | 报告里的 CR3/CR5/CR10 是集中度比；没有算 HHI 就不要写「HHI 为 xxx」 |
| 分布叠加 | 价格带/品牌/卖家国别的占比分母不同，不能相加成「合计 xx%」 |
| 排名 | 品牌 `ranking`、商品 BSR 是不同体系，不要互相比 |

### 3.1 网页登录态（sellersprite-web）特有的口径标注要求

用 `provider:'sellersprite-web'` 跑出的 run，除通用规则外还必须满足下面三条硬性标注要求：

| 项 | 要求 | 示例 |
| --- | --- | --- |
| **sample 口径要写明 N** | 所有由 Top N 样本推导的分布（价格带/评论数/评分/上架时间/品牌明细）都要标出**实际 N**——取 `market.json` 里的实际商品数，**不是** `limit` | 「价格带分布（Top 30 样本推导，N=30，非类目全量）」 |
| **估算值要写「估算」** | 类目月销额（子市场月总销量 × 类目均价）、样本口径销量/销额（样本商品数 × 近30天均量）都是推导值，必须写「估算」并给出公式与输入 | 「类目月销额约 $1.2M（估算：子市场月总销量 42,000 × 均价 $28.6）」 |
| **HHI estimated 要注明样本口径** | 品牌 HHI 只能按 Top N 样本内销量份额算，必须写「样本口径 + N + 估算」，不得表述为类目全量集中度 | 「品牌 HHI 3,180（Top 30 样本内销量份额，estimated，非类目全量）」 |

配套规则：

- **类目级品牌集中度用页面 Top3 品牌占比**（`concentration.top3BrandCrn`），不要用样本 HHI 代替；Top5/Top10 品牌集中度网页版未取到 → 写「未取到」。
- **新品占比要注明窗口**：网页版「新品占比」对应页面当前定义窗口（**默认 1 个月**），写「新品占比 x%（页面口径：1 个月）」；不与 6 个月口径并列、不当成长趋势。
- **网页版没有的分布一律「未取到」**：卖家国别、卖家类型、商品集中度、需求趋势在网页版没有对应页面；不得解读为「没有竞争」「无季节性」。
- **分布分桶是插件口径**：价格带/评论数/评分的分桶阈值由插件定义，报告写「按插件分桶（Top N 样本推导）」，不写「卖家精灵分布」。
- **跨链路不并列**：网页版 run 与 MCP 版 run 的分布口径不同（月销额一个是估算、一个是原值），跨链路比较必须标口径差异。

## 4. 缺失值处理

### 4.1 先判断「这是不是真的 0」

| 现象 | 判定 | 处理 |
| --- | --- | --- |
| 字段为 `null`/`undefined`/空串 | 未取到 | 标「未取到」，不参与计算 |
| 整个分布数组为 `[]` | 未取到（工具失败或未抓取） | 标「未取到」，不要解读为「没有竞争」 |
| 分布行全 0（products/units/revenue 全 0） | 可疑：多为样本为空/节点无效 | 标「数据异常/未取到」，不要用 0 下结论 |
| 总量为 0 但商品数>0 | 可疑：口径异常或节点错误 | 标「数据异常」，建议换叶子节点或换月份 |
| 字段是合法 0（如某价格带确实没有销量） | 真实值 | 可以写 0，但要能说明「该分布有数据且该行确实为 0」 |
| 字段是字符串 `"--"`/`"N/A"`/`""` | 未取到 | 统一按缺失处理 |

> 核心原则：**0 是数据，缺失是缺失**。分不清时按缺失处理，并在报告说明理由。

### 4.2 评分维度的降级

- 某维度输入缺失 → 引擎按**最低档**计分，并在 `scores.notes` 记录；报告必须点名该维度与缺口。
- 缺 1 个维度：可以给结论，但要写「该维按最低档，结论偏保守」。
- 缺 ≥2 个维度（`scores.json.dataQuality` = `C`/`D`，`missingDimensions` ≥2）：报告结论区已由数据质量守卫抑制——显示「数据质量 C/D（N 个维度缺数）：兜底评级仅供参考，建议补数后再评，不构成进入建议」，不出现「强烈推荐进入」。Agent 照此给「数据不足/谨慎试验 + 补数清单」，不得自行改回推荐；读取历史 run 时以 `dataQuality` 与报告结论区措辞为准（结论区含「补数后再评」即视为已抑制），产物矛盾时按报告守卫措辞手动降级并注明。
- 关键维度（市场规模/利润空间/竞争烈度）任一缺失且无法补 → 结论最多「谨慎试验」。
- 禁止「用行业常识补一个值」再算分；如果必须给参考值，只能放在「假设」段落，明确标注不是数据，且不进入评分。

### 4.3 缺失值的表达

- 报告统一用「**未取到**」（字段级）与「**数据缺口**」（维度级）两种措辞，不要写「无数据」这种容易被理解成 0 的模糊词。
- 表格里缺失单元格写「未取到」或 `—`，不要留空（留空会被误读为 0）。
- 结论里先写缺口，再写「因此本次结论的置信度/评级如何」。

## 5. 缓存与重复调用

### 5.1 复用优先

- 插件配置有 `cacheTtlHours`（默认 24）作为**建议复用窗口**；v0.1 的取数不会自动命中缓存，因此要靠 Agent 主动查历史 run 复用。
- 触发取数前先 `research_runs` `action:'list'`：若存在**同站点 + 同 nodeIdPath/类目 + 同 limit + 同 month** 且 `createdAt` 在 24 小时内 → 先问用户「复用上次运行还是重新取数（会再消耗额度）」。
- 复用 run 时，报告仍要写该 run 的 `fetchedAt` 与 `createdAt`，并注明「本次解读基于历史运行，未重新取数」。

### 5.2 什么时候必须重跑

以下任一情况，不要复用旧 run：

1. 用户明确要求刷新/换月份/换站点/换样本上限；
2. 用户这次提供了 `unitCost`（利润维度口径变了，必须重跑才能进入评分）；
3. 旧 run 的 `warnings` 显示关键分布缺失、月份回退、或分数异常；
4. 旧 run 的 `market.month` 为空且用户指定了月份；
5. 类目节点可能变化（用户换了关键词/要求换细分）。

### 5.3 禁止「钓鱼式」重试

- 同一个类目、同一组参数，不要为了「看看会不会出更好的数」连续重跑。
- 数据源报错/空结果时最多重试 1 次（换叶子节点或换月份是有依据的重试），仍失败就如实报错。
- 不得通过反复调用让多个 run 同时存在，然后只挑「看起来更有利」的那个写报告；如有多 run，必须说明口径差异并全部列在附录。

## 6. 成本告知

### 6.1 调用成本先算清

| 操作 | 消耗 | 告知话术 |
| --- | --- | --- |
| `research_provider_status` | 免费（未配置 key 不发请求） | 无需告知 |
| `research_category_select`（`provider:'sellersprite'`） | **约 9~11 次**数据源调用，消耗数据服务额度 | 「这一步会跑 1 次类目选品，内部约 9~11 次卖家精灵调用，会消耗额度，单价以面板设置为准」 |
| `research_category_select`（`provider:'sellersprite-web'`） | **3 次页面读取**（选市场 → 类目报告 → 查竞品）；不消耗 MCP 额度，占用卖家精灵**网页端查询次数** | 「这一步会跑 1 次类目选品，走你 Chrome 里已登录的卖家精灵网页版：内部读 3 个页面，不消耗 MCP 额度，但会占用网页端查询次数」 |
| `mcp_call` | 每次 1 个原始工具调用（响应过大落盘不额外计费） | 「这是第 N 次补数调用，预计再消耗 1 次调用」 |
| `research_runs` | 免费（只读本地） | 无需告知 |

- 单价以面板设置/数据源套餐为准；工具返回里没有单价时**不要编一个具体金额**，只说「按面板设置的单价计费」。若用户提供了可核对的价格，才给「约 N × 单价」的估算并注明假设。
- 失败调用是否计费以厂商规则为准；默认按可能计费对待，不要因失败就无限重试。

### 6.2 告知时机与拒绝处理

- 首次付费调用前必须告知；用户已明确说「跑」时用一句话告知后继续。
- **切换链路（MCP → 网页登录态）= 换了一种计费口径，必须重新告知**（改成占用网页端查询次数），不能默认用户同意。
- 需要重跑（歧义节点确认后、换月份、换 limit）必须**再次告知**，因为又是一组 9~11 次调用。
- 用户说「先别花额度」/「等等」→ 停止，给出不花钱的替代：查历史 run、让用户自己决定参数后再跑。
- 用户拒绝后不要换个工具偷偷取数；`mcp_call` 同样是付费。

## 7. 禁止伪造字段（硬红线）

以下行为一律禁止，出现即视为输出不合格：

1. 编造 ASIN、标题、品牌、卖家、价格、销量、销售额、评分、评论数、BSR、上架时间、退货率、集中度、增长率。
2. 用**记忆/常识/网页搜索**的数字冒充 SellerSprite 数据；外部信息只能作为「外部参考」单独标注，不能进评分与类目结论。
3. 把上游参考文档里的**示例数值**（如某个示例类目的销售额、评分案例）当成用户类目数据。
4. 把测试 fixture、占位符、模板文案写成真实数据。
5. 手工重算分数并当引擎评分输出；或为了让评级「好看」调整个别维度的输入。
6. 把估算写成数据：只有把 `unitCost` 作为参数交给 `research_category_select`、由 `scores.json` 输出（`basis='unit_cost'`）的毛利，才算评分输入；Agent 自己手算的毛利/净利只能标「推算（公式 + 输入）」，不得冒充评分或数据。
7. 用「约」「大概」修饰具体数字却不给来源；每个具体数字都要能指回字段/表格/补数记录。
8. 跨 run/跨站点/跨月份拼接数字而不标口径差异。
9. 报告里出现密钥、完整请求头、或 `mcp_call` 的敏感参数。
10. 把「未取到」写成 0、把 0 写成「没有市场」、把缺失指标写成「行业平均」。

## 8. 数据质量分级与可下结论的范围

| 等级 | 判定 | 允许的结论 |
| --- | --- | --- |
| **A 完整** | 五维输入完整（`dataQuality='A'`）；6 个分布齐全；无阻断性 warnings；样本 ≥100 | 完整评分 + 推荐进入/谨慎试验/放弃 |
| **B 基本可用** | 1 个维度缺数（`dataQuality='B'`）；或 1 个分布缺失/1 条月份节点 warning；样本 50–99 | 可给评级，但必须点名缺口、结论降档风险；报告标注「样本不足」 |
| **C 参考级** | 2 个维度缺数（`dataQuality='C'`）；样本 <50；或分数异常未核 | 报告已抑制进入建议（「补数后再评，不构成进入建议」）；对用户结论只给「数据不足 + 补数清单 + 初步观察」 |
| **D 不可用** | ≥3 个维度缺数（`dataQuality='D'`）/无评分；`NO_CREDENTIAL`/`EMPTY_MARKET`/接口失败/无 run | 不给任何类目结论，只报错误/补数清单与下一步 |

> `dataQuality` 只由「评分维度缺数个数」决定（0→A、1→B、2→C、≥3→D），样本量/分布缺失只影响标注，不改这个字段；无评分时 `dataQuality=null`、`missingDimensions=0`（两个字段始终存在）。
>
> 维度「缺数」的判定优先级：`dimensions[].inputs.missing === true`（引擎显式标记）> 旧版分数数据的 `inputs.estimated === true` > `detail` 文案含「缺少/数据缺失/按最低档」。Agent 直接读 `scores.json.dataQuality` / `missingDimensions` 即可，不要自己按文案重判。
>
> 网页登录态链路下，卖家国别/卖家类型/商品集中度/需求趋势分布为空数组属**常态**（网页版没有对应页面），不计入 `missingDimensions`、也不改 `dataQuality`；但报告必须把它们写「未取到」，不能解读为「没有竞争」。

分级写进报告头部（「数据质量：B」），让读者知道结论的置信度。

## 9. 审计与可追溯

- 一次运行的完整凭据：`runId` + `dir` + `manifest`（params/usage/fetchedAt/warnings）+ `scores.json` + `report.md` + `artifacts`。
- 报告附录必须列：数据源、站点、类目、NodeIdPath、数据月份、抓取时间、样本口径、成本口径、补数记录（provider/tool/args/时间）、`warnings` 原文。
- 不删除/不覆盖旧 run；需要新结论就新跑一个 run（runId 冲突会自动加 `-2`）。
- 可复现基线：同 provider + 同站点 + 同 nodeIdPath + 同 limit + 同 month + 同 unitCost → 结果应基本一致；否则要说明原因（数据源更新/月份回退/节点变化）。
- 冲突处理优先级：**运行产物（market.json/scores.json）> 工具摘要 > 手工补数 > 模型推断**。发现冲突要写「口径差异待核」，两值并列，不偷偷选一个。
- `research_runs get` 返回的 `reportMd` 超过 30000 字符会被截断；引用完整报告时读 `dir/report.md`。

## 10. 安全与隐私

- 不向用户索要密钥、不回显密钥、不把密钥写进 args/日志/报告；用户主动贴出密钥时，提醒「请去设置页填写并考虑轮换」，不要复述。
- 不绕过登录/验证码/付费墙；不直连数据源（插件已托管 HTTP 客户端与认证）。
- 不把用户业务数据（成本、供应链信息）写进与结论无关的公开字段；报告只引用结论所需数据。
- `mcp_call` 的 `args` 只放业务参数，不放任何鉴权信息。

## 11. 固定沟通句式（照用，少踩坑）

**付费告知**

```text
说明：这次会跑 1 次类目选品，内部约 9~11 次卖家精灵调用，会消耗你的数据源额度（单价以面板设置为准）。
如果你同意，我就开始；不想消耗额度的话，我们可以先看历史运行。
```

**网页登录态付费告知**

```text
说明：这次会跑 1 次类目选品，走你 Chrome 里已登录的卖家精灵网页版：内部读 3 个页面（选市场/类目报告/查竞品），不消耗 MCP 额度，但会占用卖家精灵网页端的查询次数。
口径提醒：价格带/评论数/上架时间分布由 Top N 样本推导，类目月销额为估算值，报告会逐项标注。
```

**复用历史**

```text
我发现 11 月 9 日跑过一次同站点、同类目、同样本上限的运行（runId: ...），数据抓取于 ...
可以直接复用这份产物（不消耗额度），也可以重新取数（约 9~11 次调用）。你选哪个？
```

**报告缺口**

```text
数据缺口：卖家类型分布（FBA/FBM/AMZ 占比）本次未取到，因此「履约门槛」这一项只做定性提示，不参与评分。
其余五维输入完整，评分为 ...（数据质量：B）。
```

**失败处理**

```text
取数失败：<原始错误 code + message>。
这通常是 <key 未配置 / 节点无效 / 月份未就绪 / 额度不足> 导致，建议 <去设置页 / 换叶子节点 / 换月份 / 充值>。
在解决前我不会再调用付费工具，也不会用其他方式拼数据。
```

**降级给出结论**

```text
由于数据质量 C（缺少 ≥2 个评分维度），报告已标「补数后再评，不构成进入建议」，本次不给进入建议；先给补数清单与初步观察：
1) 需要补：...
2) 补齐后重跑约消耗 9~11 次调用。
初步观察（非评级）：...
```

## 12. 输出前数据自检

- [ ] 报告头部含来源/runId/站点/类目/NodeIdPath/数据月份/抓取时间/样本口径/成本口径。
- [ ] 缺失字段与缺失维度都显式标注，没有被 0 或常识替代。
- [ ] 所有百分数刻度正确，0~1 与 0~100 不混。
- [ ] 没有跨站点/跨月份/跨 limit 拼数；跨 run 对照已标口径。
- [ ] 付费调用次数已记录，且每次调用前都告知过用户。
- [ ] 报告里没有密钥、没有未标注的估算、没有伪造字段。
- [ ] 数据质量等级（A/B/C/D）已写入报告，并匹配对应结论强度。
- [ ] 补数记录（如有）含 provider/tool/args/时间/落盘路径。
